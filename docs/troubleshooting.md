# Troubleshooting

Find the error you got. Each one names what is mis-wired and where the fix lives.

## Errors from this package

| Error                                                                 | What is mis-wired                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `The test suite could not reach a container runtime.`                 | Docker is not running. Start it and run the tests again.                                                                                                                                                                                                                                                                                                                                             |
| ``Could not resolve the `prisma` CLI from <cwd>.``                    | The `prisma` peer dependency is not installed. The harness migrates with your project's own Prisma.                                                                                                                                                                                                                                                                                                  |
| `` `prisma migrate deploy` failed: ``                                 | Your migrations failed to apply; Prisma's own output follows. If it reads `The datasource.url property is required in your Prisma config file`, `prisma.config.ts` is missing or lacks a `datasource.url`: see [Prisma config](setup.md#1-prisma-config).                                                                                                                                            |
| `cloning the Worker Databases from <name> failed:`                    | `CREATE DATABASE … TEMPLATE` failed, usually because of another connection to the template, or a Postgres image that does not support the clone.                                                                                                                                                                                                                                                     |
| `VITEST_POOL_ID is not set —`                                         | `setupWorkerDatabase()` ran outside a Vitest worker. It must run from a file listed in `setupFiles`, with `pool: "forks"` set: see [Vitest config](setup.md#5-vitest-config).                                                                                                                                                                                                                        |
| `No Template Database was provided to this run —`                     | The global setup did not run. Register your global-setup file as `globalSetup: ["tests/global-setup.ts"]`: see [Vitest config](setup.md#5-vitest-config).                                                                                                                                                                                                                                            |
| `refusing to reset <name> — only Worker Databases`                    | `DATABASE_URL` does not name a Worker Database when `setupDatabase(db)` runs. **Read `<name>` in the message first.** Usually the setup file is missing from `setupFiles`, so `DATABASE_URL` is still your dev one; otherwise something reassigned it after `setupWorkerDatabase()` ran. This guard is the last line stopping the Reset from emptying a real database.                               |
| `refusing to reset — no Worker Database is configured for this file.` | `DATABASE_URL` is unset, or the global setup provided no Template Database: register the setup file in `setupFiles` and the global-setup file in `globalSetup`.                                                                                                                                                                                                                                      |
| `the client passed to setupDatabase() is connected to <name>, but`    | The client you passed is not on this worker's database. Either the setup file imports your app statically, so the client was built before `DATABASE_URL` was assigned (see [Per-worker setup](setup.md#4-per-worker-setup)), or your client module reads another variable or a hard-coded URL: build it from `DATABASE_URL` (see [Your Prisma client module](setup.md#2-your-prisma-client-module)). |
| `setupDatabase() was called twice in this file`                       | Remove one of the calls; keep the one at the top of the file.                                                                                                                                                                                                                                                                                                                                        |
| `the Reset could not empty <name>:`                                   | Postgres's own message follows. If it is a lock timeout, a connection the test opened still holds a lock: an un-awaited query, or a transaction a second client never ended. Finish both before the test ends: see [Finish what a test opens](writing-tests.md#finish-what-a-test-opens).                                                                                                            |

## Errors from the toolchain and Postgres

These come from Vite, Next.js, pnpm, your own client module or Postgres, not from this
package, but they are the usual first failures when wiring an app.

| Error                                                                         | What is mis-wired                                                                                                                                                                                              |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Cannot find package '@/lib/db'` (or any other alias)                         | The project uses `tsconfig.json` path aliases and Vitest does not resolve them: see [Path aliases](setup.md#path-aliases).                                                                                     |
| `This module cannot be imported from a Client Component module`               | Your client module imports `server-only`, which needs an alias in the Vitest config: see [`server-only`](setup.md#server-only).                                                                                |
| `The server does not support SSL connections`                                 | Your app turns on TLS from an environment variable, and the test container speaks plaintext. Set that variable to its off value in the setup file: see [TLS](setup.md#tls).                                    |
| `ERR_PNPM_IGNORED_BUILDS` (`cpu-features`, `ssh2`, `protobufjs`)              | pnpm wants a decision on build scripts that come in through testcontainers. The harness needs none of them built: list them as `false` under `allowBuilds`, see [Before you start](setup.md#before-you-start). |
| `DATABASE_URL is not set` from `next build` or another command outside Vitest | Your client module throws at import, and a command that needs no database imports it. Build the client on first use instead: see [Database-free commands](setup.md#database-free-commands).                    |
